00전체 구조

이 서버(105.24.1.170)엔 이미 다른 시스템이 IIS 8080 사이트로 떠 있습니다(건드리지 않음). 도로대장 시스템은 같은 서버에 나란히 새 IIS 사이트(11800)로 추가하는 구성입니다.

사용자 브라우저

→

→

포트가 8080이 아니라 11800인 이유 — 8080은 기존 시스템이 이미 쓰고 있어서, 도로대장 시스템은 겹치지 않게 11800로 새 사이트를 만듭니다(보안팀에 개방 요청 완료). 3000(Node)과 5432(PostgreSQL)는 로컬 전용이라 방화벽에서 외부 노출을 막습니다.

01사전 준비물

서버 쪽에 이미 되어 있어야 하는 것과, 이 컴퓨터(로컬)에서 이미 준비된 것을 나눠서 확인합니다. ⚠ 이 서버는 IT팀이 "서버 자원 할당·OS·IP·계정"만 세팅 완료했고, 아래 항목들은 우리가 직접 설치/확인해야 합니다.

서버(105.24.1.170)에서 직접 설치/확인해야 하는 것

  • PostgreSQL은 이미 설치돼 있음 — 다만 포트·계정 정보를 몰라서 직접 확인해야 함. 아래 "PostgreSQL 포트·계정 확인" 절차 참고
  • Node.js 설치 여부 확인(미확인 — node -v로 먼저 확인)
  • IIS는 이미 설치돼 있음(8080에 다른 시스템). URL Rewrite + Application Request Routing(ARR) 모듈 설치 여부 확인, "Server Proxy Settings → Enable proxy" 체크 필요(안 하면 502)
  • 방화벽 인바운드 11800만 허용 (3000, 5432는 외부 노출 금지) — 보안팀에 요청 완료
  • SFTP 구동 여부 미확인 — 이전 서버는 FreeSFTPd(Dsuser 계정, Home Directory D:\)를 썼으나, 이 서버에 준비돼 있는지는 확인 전(없으면 원격데스크톱으로 직접 업로드하거나 새로 설치)

PostgreSQL 포트·계정 확인 (원격데스크톱 105.24.1.170:33890 접속 후, PowerShell)

  • 1) 서비스 확인 — 이름이 "postgresql"로 안 시작할 수도 있음: Get-Service | Where-Object { $_.DisplayName -like "*postgres*" }
  • 2) 설치 경로 확인: Get-ChildItem "C:\Program Files\PostgreSQL" — 버전 폴더 이름을 기억해둘 것
  • 3) 실제 포트 확인(프로세스 기준, 설정파일보다 확실함): Get-NetTCPConnection -OwningProcess (Get-Process postgres).Id | Select-Object LocalPort
  • 4) 계정·비밀번호 — 기존 비번은 해시로만 저장돼 "알아낼" 수 없음. 모르면 우리 전용 계정을 새로 만드는 게 안전(기존 데이터는 안 건드림):
  • 4-a) data\pg_hba.conf의 local 인증 방식을 적어두고 임시로 trust로 변경(백업 필수)
  • 4-b) 서비스 재시작 — ⚠ 이 순간 기존 시스템의 DB 연결도 잠깐 끊김, 영향 적은 시간대에 진행
  • 4-c) 비번 없이 접속: psql -U postgres -h 127.0.0.1 -p <확인한 포트>
  • 4-d) 새 계정 생성: CREATE USER "DSMap" WITH PASSWORD '...'; CREATE DATABASE "DSMap" OWNER "DSMap";
  • 4-e) pg_hba.conf를 원래대로 복구 후 서비스 재시작

로컬(이 컴퓨터)에 이미 준비된 것

  • server/env.production — 운영 값이 이미 채워짐 (DB 접속정보, 세션시크릿, VWorld 키)
  • server/ecosystem.config.js — PM2 실행 설정 (앱 이름 road-ledger)
  • deploy/web.config — IIS 리버스프록시 규칙
  • server/db/schema.sql, server/db/seed-admin.js

03SFTP로 파일 업로드

업로드 대상: D:\Dsmap_ROAD (SFTP 접속 시 /Dsmap_ROAD로 보임). WinSCP 등으로 접속합니다.

경로포함 여부비고
server/ (전체)포함아래 제외 항목만 빼고
public/ (전체)포함
deploy/web.config포함D:\Dsmap_ROAD 최상위에 (deploy 폴더째로 올리면 안 됨)
server/node_modules/제외서버에서 npm install로 새로 설치
server/.env제외로컬 개발(Docker 테스트 DB)용, 운영에 올리면 안 됨
server/uploads/ 내용물제외폴더 자체는 있어야 함, 내용은 비워도 됨
.vscode/, README.md제외없어도 동작 지장 없음(참고용)
이번에 겪은 문제들

숨김 파일 문제 — WinSCP에서 점(.)으로 시작하는 .env.production이 목록에 안 보이거나 선택이 안 될 수 있습니다. WinSCP 옵션 → 환경설정 → 패널 → "숨김 파일 표시" 체크하거나, 로컬에서 env.production.txt처럼 임시로 점 없는 이름으로 바꿔 올린 뒤 서버 도착 후 다시 이름을 바꾸세요.

SFTP 접근 권한 — FreeSFTPd의 Dsuser 계정이 실제로 해당 폴더 접근 권한이 있어야 합니다. 탐색기 "보안" 탭의 NTFS 권한과 FreeSFTPd 자체 계정 권한은 다를 수 있으니, 접속이 안 되면 FreeSFTPd 관리자 프로그램에서 Dsuser의 Home Directory·권한을 직접 확인하세요.

05PM2로 상시 구동

터미널 창을 띄워두는 방식이 아니라, PM2가 백그라운드에서 road-ledger 프로세스를 관리하고 재부팅 후에도 자동으로 살아나게 합니다.

PowerShell — 최초 1회만
npm install -g pm2 pm2-windows-startup
pm2-startup install
PowerShell — 앱 시작
cd D:\Dsmap_ROAD\server
pm2 start ecosystem.config.js
pm2 save
재배포 시
pm2 restart road-ledger
로그 확인
pm2 logs road-ledger --lines 50

06IIS 사이트 생성 (최초 1회)

  1. IIS 관리자에서 새 웹사이트 추가 — 포트 11800, 물리 경로 D:\Dsmap_ROAD
  2. 사이트 선택 → "인증(Authentication)" → 익명 인증 = 사용, Windows 인증 = 사용 안 함 — 이거 안 하면 401 오류
  3. NTFS 권한 부여:
PowerShell (관리자)
icacls "D:\Dsmap_ROAD" /grant "IIS_IUSRS:(OI)(CI)RX" /T

접속 테스트: http://105.24.1.170:11800 → 로그인 화면이 뜨는지 확인합니다.

08트러블슈팅

지난 배포 때 실제로 겪은 증상과 원인입니다.

401 - Unauthorized: Access is denied due to invalid credentials

IIS 인증 설정 문제입니다. 06단계의 익명 인증 활성화 + NTFS IIS_IUSRS 권한을 확인하세요. URL Rewrite가 동작하기도 전에 IIS 인증 단계에서 막히는 것이라 web.config 내용과는 무관합니다.

로그인 화면은 뜨는데 로그인이 안 됨

정적 파일은 잘 서빙된다는 뜻이라 IIS↔Node 리버스프록시 자체는 정상입니다. 문제는 POST 요청(/api/auth/login) 쪽 — 브라우저 F12 → Network 탭에서 login 요청의 상태 코드를 확인하세요.

증상원인
상태코드 500서버(Node) 에러 — pm2 logs road-ledger --lines 50으로 확인
상태코드 405 / 501IIS WebDAV 모듈이 POST를 가로챔 — 사이트의 "모듈"/"핸들러 매핑"에서 WebDAVModule 제거·사용 안 함
Network에 요청 자체가 안 뜸Console 탭에서 JS 에러 확인
로그: "password authentication failed".env의 PGPASSWORD가 실제 PostgreSQL DSMap 계정 비밀번호와 다름
로그: "ECONNREFUSED"PostgreSQL이 5432에서 안 열려있거나 로컬 접속 차단(pg_hba.conf, listen_addresses 확인)

WinSCP로 Dsmap_ROAD 접속 시 "No such file"

폴더가 아직 없거나, FreeSFTPd에서 Dsuser 계정에 해당 경로 접근 권한이 없는 경우입니다. FreeSFTPd 관리자 프로그램에서 Home Directory·권한을 직접 확인하세요 — Windows NTFS 권한과는 별개의 문제일 수 있습니다.

배포 후 지도/지적도가 안 뜸 (VWorld 401/403)

07단계의 DSRoad 전용 키로 이미 교체했습니다. 그래도 안 뜨면 VWorld 개발자센터 "인증키 관리"에서 서비스 URL이 실제 접속 주소(스킴·포트 포함)와 정확히 일치하는지 확인하세요.

09재배포(업데이트) 시

  1. 로컬에서 수정한 파일만 SFTP로 D:\Dsmap_ROAD에 재업로드 (server/.env, node_modules, uploads는 매번 제외)
  2. DB 스키마가 바뀌었다면 변경분만 psql로 반영
  3. 서버에서: pm2 restart road-ledger
  4. 프론트엔드(public/)만 바뀐 경우 서버 재시작 불필요 — 브라우저 새로고침(캐시 때문에 안 바뀐 것처럼 보이면 Ctrl+F5)으로 충분

10완료 확인

  • http://105.24.1.170:11800 접속 시 로그인 화면이 뜨는지
  • 아이디/비밀번호로 로그인이 되는지 (POST /api/auth/login 정상 응답)
  • 로그인 후 지도 타일이 정상적으로 뜨는지 (VWorld 키 확인)
  • DXF/DWG 도면을 열어봤을 때 정상 표시되는지
  • 서버를 재부팅해도 pm2가 road-ledger를 자동으로 다시 띄우는지
  • 8080의 기존 시스템이 이 배포로 영향받지 않았는지
