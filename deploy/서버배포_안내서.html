00전체 구조

이 서버엔 이미 DS-LandInfo(기존 Electron 앱)가 IIS 8080 사이트로 떠 있습니다. 도로대장 시스템은 같은 서버에 나란히 새 IIS 사이트(8081)로 추가하는 구성입니다.

🌐
사용자 브라우저
http://192.168.0.211:8081
→
🛡️
IIS (새 사이트)
8081, URL Rewrite + ARR로 프록시
→
⚙️
Node.js (road-ledger)
내부 3000, PM2로 상시 구동
→
🗄️
PostgreSQL
DSMap / DSMap, 5432, 로컬 전용

포트가 8080이 아니라 8081인 이유 — 8080은 DS-LandInfo가 이미 쓰고 있어서, 도로대장 시스템은 겹치지 않게 8081로 새 사이트를 만듭니다. 3000(Node)과 5432(PostgreSQL)는 로컬 전용이라 방화벽에서 외부 노출을 막습니다.

01사전 준비물

서버 쪽에 이미 되어 있어야 하는 것과, 이 컴퓨터(로컬)에서 이미 준비된 것을 나눠서 확인합니다.

서버(192.168.0.211)에 이미 되어 있어야 하는 것

  • PostgreSQL 설치 — 포트 5432, 계정/DB 이름 모두 DSMap으로 생성
  • Node.js 설치
  • IIS + URL Rewrite + Application Request Routing(ARR) 모듈, "Server Proxy Settings → Enable proxy" 체크 완료(안 하면 502)
  • 방화벽 인바운드 8081만 허용 (3000, 5432는 외부 노출 금지)
  • FreeSFTPd 구동 중 — Dsuser 계정 Home Directory = D:\ (SFTP에서 /Dsmap_ROAD = 실제 D:\Dsmap_ROAD)

로컬(이 컴퓨터)에 이미 준비된 것

  • server/env.production — 운영 값이 이미 채워짐 (DB 접속정보, 세션시크릿, VWorld 키)
  • server/ecosystem.config.js — PM2 실행 설정 (앱 이름 road-ledger)
  • deploy/web.config — IIS 리버스프록시 규칙
  • server/db/schema.sql, server/db/seed-admin.js

02로컬에 준비된 파일 구조

road-ledger-app 폴더 기준입니다. 이 구조 그대로 서버에 옮깁니다.

road-ledger-app/ ├─ server/ │ ├─ .env.production # 운영값 채워진 파일 — 서버에서 .env로 이름 변경 │ ├─ ecosystem.config.js # PM2 실행 설정 │ ├─ db/ │ │ ├─ schema.sql # DB 테이블 생성 스크립트 │ │ └─ seed-admin.js # 관리자 계정 생성 스크립트 │ └─ (index.js, config.js, db.js, routes/, middleware/, package.json 등) ├─ public/ # 프론트엔드 전체 └─ deploy/ ├─ web.config # IIS 리버스프록시 설정 — D:\Dsmap_ROAD 최상위로 └─ 서버배포_가이드.txt

03SFTP로 파일 업로드

업로드 대상: D:\Dsmap_ROAD (SFTP 접속 시 /Dsmap_ROAD로 보임). WinSCP 등으로 접속합니다.

경로포함 여부비고
server/ (전체)포함아래 제외 항목만 빼고
public/ (전체)포함
deploy/web.config포함D:\Dsmap_ROAD 최상위에 (deploy 폴더째로 올리면 안 됨)
server/node_modules/제외서버에서 npm install로 새로 설치
server/.env제외로컬 개발(Docker 테스트 DB)용, 운영에 올리면 안 됨
server/uploads/ 내용물제외폴더 자체는 있어야 함, 내용은 비워도 됨
.vscode/, README.md제외없어도 동작 지장 없음(참고용)
이번에 겪은 문제들

숨김 파일 문제 — WinSCP에서 점(.)으로 시작하는 .env.production이 목록에 안 보이거나 선택이 안 될 수 있습니다. WinSCP 옵션 → 환경설정 → 패널 → "숨김 파일 표시" 체크하거나, 로컬에서 env.production.txt처럼 임시로 점 없는 이름으로 바꿔 올린 뒤 서버 도착 후 다시 이름을 바꾸세요.

SFTP 접근 권한 — FreeSFTPd의 Dsuser 계정이 실제로 해당 폴더 접근 권한이 있어야 합니다. 탐색기 "보안" 탭의 NTFS 권한과 FreeSFTPd 자체 계정 권한은 다를 수 있으니, 접속이 안 되면 FreeSFTPd 관리자 프로그램에서 Dsuser의 Home Directory·권한을 직접 확인하세요.

04.env 적용 & 스키마 반영

여기부터는 SFTP가 아니라 RDP로 서버에 직접 접속해서 PowerShell(관리자 권장)로 실행합니다.

  1. 파일명 변경: D:\Dsmap_ROAD\server\.env.production → .env
PowerShell
Rename-Item "D:\Dsmap_ROAD\server\.env.production" ".env"

이 파일엔 이미 운영 값이 채워져 있습니다 — 그대로 두면 됩니다.

server/.env (이미 채워진 내용)
PORT=3000                                          # IIS가 8081에서 이 내부 포트로 프록시
PGHOST=localhost
PGPORT=5432
PGDATABASE=DSMap
PGUSER=DSMap
PGPASSWORD=••••••••                                   # 이미 설정됨
SESSION_SECRET=••••••••••••••••••••••••                # 이미 무작위 값으로 생성됨(2026-08-05)
VWORLD_API_KEY=••••••••••••••••••••••••••••••••••••   # DSRoad 전용 개발키, 만료 2027-02-28
VWORLD_REFERER=https://192.168.0.211:8081/
ITS_CCTV_API_KEY=••••••••••••••••••••••••••••••••
UPLOAD_DIR=./uploads
  1. 스키마 적용:
PowerShell
psql -h localhost -p 5432 -U DSMap -d DSMap -f D:\Dsmap_ROAD\server\db\schema.sql
  1. 패키지 설치 + 관리자 계정 생성:
PowerShell
cd D:\Dsmap_ROAD\server
npm install --omit=dev
node db\seed-admin.js 아이디 비밀번호 표시이름

05PM2로 상시 구동

터미널 창을 띄워두는 방식이 아니라, PM2가 백그라운드에서 road-ledger 프로세스를 관리하고 재부팅 후에도 자동으로 살아나게 합니다.

PowerShell — 최초 1회만
npm install -g pm2 pm2-windows-startup
pm2-startup install
PowerShell — 앱 시작
cd D:\Dsmap_ROAD\server
pm2 start ecosystem.config.js
pm2 save
재배포 시
pm2 restart road-ledger
로그 확인
pm2 logs road-ledger --lines 50

06IIS 사이트 생성 (최초 1회)

  1. IIS 관리자에서 새 웹사이트 추가 — 포트 8081, 물리 경로 D:\Dsmap_ROAD
  2. 사이트 선택 → "인증(Authentication)" → 익명 인증 = 사용, Windows 인증 = 사용 안 함 — 이거 안 하면 401 오류
  3. NTFS 권한 부여:
PowerShell (관리자)
icacls "D:\Dsmap_ROAD" /grant "IIS_IUSRS:(OI)(CI)RX" /T

접속 테스트: http://192.168.0.211:8081 → 로그인 화면이 뜨는지 확인합니다.

07VWorld 키 확인

8081 전용으로 새로 발급한 키입니다 — 04단계의 .env와 값이 정확히 일치하는지만 확인하면 됩니다.

서비스명
DSRoad
서비스 URL
https://192.168.0.211:8081
키 종류
개발키
발급일 → 만료일
2026-08-28 → 2027-02-28
개발키는 만료됩니다

기존에는 같은 서버의 DS-LandInfo가 등록해 쓰던 키(FF96060E-...)를 재사용했지만, 이제 DSRoad 전용 키로 교체했습니다. 이 키는 2027-02-28에 만료되는 개발키입니다(연장신청 0/3회 사용 가능) — 만료 전에 VWorld 개발자센터에서 운영키 신청으로 전환해야 지도가 끊기지 않습니다.

서버 접속 주소(도메인 연결, 포트 변경 등)가 바뀌면 이 키의 서비스 URL도 같이 재등록해야 합니다.

08트러블슈팅

지난 배포 때 실제로 겪은 증상과 원인입니다.

401 - Unauthorized: Access is denied due to invalid credentials

IIS 인증 설정 문제입니다. 06단계의 익명 인증 활성화 + NTFS IIS_IUSRS 권한을 확인하세요. URL Rewrite가 동작하기도 전에 IIS 인증 단계에서 막히는 것이라 web.config 내용과는 무관합니다.

로그인 화면은 뜨는데 로그인이 안 됨

정적 파일은 잘 서빙된다는 뜻이라 IIS↔Node 리버스프록시 자체는 정상입니다. 문제는 POST 요청(/api/auth/login) 쪽 — 브라우저 F12 → Network 탭에서 login 요청의 상태 코드를 확인하세요.

증상원인
상태코드 500서버(Node) 에러 — pm2 logs road-ledger --lines 50으로 확인
상태코드 405 / 501IIS WebDAV 모듈이 POST를 가로챔 — 사이트의 "모듈"/"핸들러 매핑"에서 WebDAVModule 제거·사용 안 함
Network에 요청 자체가 안 뜸Console 탭에서 JS 에러 확인
로그: "password authentication failed".env의 PGPASSWORD가 실제 PostgreSQL DSMap 계정 비밀번호와 다름
로그: "ECONNREFUSED"PostgreSQL이 5432에서 안 열려있거나 로컬 접속 차단(pg_hba.conf, listen_addresses 확인)

WinSCP로 Dsmap_ROAD 접속 시 "No such file"

폴더가 아직 없거나, FreeSFTPd에서 Dsuser 계정에 해당 경로 접근 권한이 없는 경우입니다. FreeSFTPd 관리자 프로그램에서 Home Directory·권한을 직접 확인하세요 — Windows NTFS 권한과는 별개의 문제일 수 있습니다.

배포 후 지도/지적도가 안 뜸 (VWorld 401/403)

07단계의 DSRoad 전용 키로 이미 교체했습니다. 그래도 안 뜨면 VWorld 개발자센터 "인증키 관리"에서 서비스 URL이 실제 접속 주소(스킴·포트 포함)와 정확히 일치하는지 확인하세요.

09재배포(업데이트) 시

  1. 로컬에서 수정한 파일만 SFTP로 D:\Dsmap_ROAD에 재업로드 (server/.env, node_modules, uploads는 매번 제외)
  2. DB 스키마가 바뀌었다면 변경분만 psql로 반영
  3. 서버에서: pm2 restart road-ledger
  4. 프론트엔드(public/)만 바뀐 경우 서버 재시작 불필요 — 브라우저 새로고침(캐시 때문에 안 바뀐 것처럼 보이면 Ctrl+F5)으로 충분

10완료 확인

  • http://192.168.0.211:8081 접속 시 로그인 화면이 뜨는지
  • 아이디/비밀번호로 로그인이 되는지 (POST /api/auth/login 정상 응답)
  • 로그인 후 지도 타일이 정상적으로 뜨는지 (VWorld 키 확인)
  • DXF/DWG 도면을 열어봤을 때 정상 표시되는지
  • 서버를 재부팅해도 pm2가 road-ledger를 자동으로 다시 띄우는지
  • DS-LandInfo(8080 사이트)가 이 배포로 영향받지 않았는지
